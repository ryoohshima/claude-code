# Gemini CLI 連携ガイドライン

このファイルは、Claude Code から Gemini CLI を併用する際の判断基準と呼び出し標準を定めるものです。Gemini を補助モデルとして使い、メインの作業文脈を汚さずに別視点や最新情報を取り込むことを目的とします。

## 前提

- 実行コマンド: `gemini`（macOS では `/opt/homebrew/bin/gemini`、v0.38.2 で動作確認）
- 結果は JSON で受け取り、`jq` で `.response` のみを抽出してメインコンテキストの汚染を防ぐ
- `gemini` がインストールされていない環境では本ガイドラインは適用しない

## 標準呼び出しテンプレート

```bash
gemini -p "<簡潔なプロンプト>" --output-format json 2>/dev/null | jq -r '.response'
```

- プロンプトは目的のみを 1〜2 文で渡す（長文のコードや diff は渡さない）
- `2>/dev/null` で stderr を握り潰し、stdout の `.response` 文字列のみを採用する
- 出力が空文字列の場合は失敗扱いとし、Claude 側で代替手段（`WebSearch` / `WebFetch` / 自力推論）に切り替える

## 発火条件（呼ぶべきとき）

### 1. 最新情報・Web 検索

- ライブラリの最新版、CVE、リリース日程、API 仕様変更などリアルタイム性のある事実確認
- Claude の知識カットオフを跨ぐ可能性がある問い

### 2. セカンドオピニオン

- 設計判断、コードレビュー、バグ仮説で別モデルの視点が欲しいとき
- ユーザーが「他の意見も聞きたい」と明示したとき
- 本番影響の大きい変更前に 2 モデル合意を取りたいとき

### 3. コンテキスト節約

- 巨大ログ・diff・ドキュメントの要約のみが必要なとき（中身を Claude のコンテキストに載せたくない）
- 命名候補出し、英訳、正規表現テストなどの軽量変換

### 4. 重要事実のダブルチェック

- DB マイグレーション、認証、課金など本番影響の大きい変更前の事実確認
- ドキュメント記載の用語・表記の二重チェック

## 呼ばないとき

- コードベース内の探索や実装判断（これは Claude の責務）
- ファイル編集・コマンド実行など副作用を伴う作業
- 機密情報（社内コード、認証情報、未公開仕様）を含むプロンプト

## 結果の取り扱い

- Gemini の出力は「参考情報」として扱う。コードへ反映する前に Claude が必ず一次ソース（公式ドキュメント、リポジトリ、テスト）で裏取りする
- セカンドオピニオンで意見が割れた場合は、ユーザーに判断を仰ぐ
- 出力をそのままユーザーへ提示する場合は「Gemini からの回答」と明示し、自身の見解と区別する
